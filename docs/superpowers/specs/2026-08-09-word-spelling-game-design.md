# 영어 철자 완성 게임 설계

## 문서 상태

- 상태: 사용자 승인 완료, 구현 전 설계
- 승인일: 2026-08-09
- 목표 버전: 1.12.0
- 구현 범위: 학생용 철자 게임과 독립 리더보드

## Summary

학생이 영어 단어의 일부 철자를 단서로 확인하고, 키보드로 단어 전체를 입력하는 새로운 게임을 추가한다. 기존 행맨의 학습 방식인 "가려진 철자 완성"은 유지하되, 매달린 사람이나 실패를 연상시키는 시각 요소는 사용하지 않는다.

게임 이름은 구현 단계의 기본 표시명으로 철자 완성 게임을 사용한다. 학생 홈의 게임 활동 영역에서는 단어 낚시와 영어 단어 타자 게임 사이에 버튼을 배치한다.

새 게임은 기존 영어 단어 타자 게임과 별도의 활동 유형과 Firestore 컬렉션을 사용한다. 리더보드 저장·조회·교사 관리에는 기존 공통 리더보드 흐름을 재사용하되, 두 게임의 점수와 기록은 서로 섞지 않는다.

## Goals

- 초등학생이 영어 단어 철자를 직접 써 보는 진입 장벽을 낮춘다.
- 키보드로 정답 단어 전체를 입력하게 하여 철자 기억을 연습한다.
- 단어 길이에 따라 가림 단서를 자동 조절한다.
- 긴 단어에는 첫 글자와 끝 글자뿐 아니라 중간 철자도 표시한다.
- 게임을 다시 시작할 때마다 중간 단서 위치를 랜덤으로 바꾼다.
- 한 문제당 최대 3번 입력하고, 시도 횟수에 따라 점수를 차등 부여한다.
- 결과 화면에서 학생 이름과 점수를 별도 철자 리더보드에 등록한다.
- 기존 교사 리더보드 화면에서 철자 리더보드를 조회하고 관리할 수 있게 한다.

## Non-Goals

- 기존 WordTypingGame.jsx의 동작이나 점수 규칙을 변경하지 않는다.
- 사용자 정의 알파벳 버튼 키보드는 만들지 않는다. 학생은 실제 키보드 또는 기기 입력창을 사용한다.
- 타자 속도, 분당 타수, 시간 보너스를 핵심 점수로 사용하지 않는다.
- 행맨의 교수대, 매달린 캐릭터, 목숨 차감과 같은 폭력적 표현을 사용하지 않는다.
- 이번 1차 구현에서는 개인 성장 기록 프로필 필드를 새로 확장하지 않는다. 결과 화면의 철자 리더보드 등록이 우선 범위다.
- 교사가 실시간으로 문제를 출제하는 세션형 게임은 만들지 않는다.

## Chosen Approach

기존 공통 리더보드 정의에 spelling 활동 유형을 추가하고, spellingLeaderboards 컬렉션을 별도로 만든다. 게임 화면은 기존 타자 게임에 코드를 덧붙이지 않고 독립 컴포넌트로 만든다.

이 구조를 선택하는 이유는 다음과 같다.

- 철자 게임과 타자 게임의 점수 의미가 달라 기록을 섞지 않을 수 있다.
- 기존 주간·월간·연간·우리 학교 범위와 교사 관리 기능을 재사용할 수 있다.
- WordTypingGame.jsx가 이미 큰 파일이므로 새 기능을 별도 파일에서 관리할 수 있다.
- Firestore 규칙과 저장 함수에 활동별 검증을 추가해 잘못된 점수 저장을 막을 수 있다.

## User Experience

### 학생 홈 진입

학생 홈의 게임 버튼 순서는 다음과 같다.

단어 짝 맞추기 | 단어 낚시 | 철자 완성 게임 | 영어 단어 타자 게임 | 학급 빙고 게임

게임 버튼을 누르면 현재 불러온 단어 세트를 사용한다. 단어 세트가 없으면 게임 화면으로 이동하지 않고 학교·선생님·학년·단원을 먼저 선택하도록 안내한다.

### 시작 화면

시작 화면에는 다음 항목을 표시한다.

- 현재 단원 또는 불러온 단어 세트 이름
- 총 문제 수
- 가려진 철자를 보고 전체 단어를 써 보세요.라는 설명
- 게임 시작 버튼
- 홈으로 버튼

게임 시작은 교육용 주요 단계 버튼이므로 기존 gi-pulse 아우라 강조 효과를 적용한다.

### 플레이 화면

한 문제에 집중할 수 있도록 단일 문제 카드 구조를 사용한다.

- 현재 문제 번호와 전체 문제 수
- 진행률 표시
- 한국어 뜻
- 철자 단서 카드
- 영어 전체 단어 입력창
- 입력 확인 버튼
- 시도 횟수와 현재 점수 안내
- 피드백 메시지
- 완료 후 활성화되는 다음 문제 버튼

학생은 단서에 표시된 일부 글자를 참고하되, 정답 단어 전체를 입력한다. 입력창에서 Enter 키를 눌러도 입력 확인과 같은 동작을 수행한다.

정답을 맞히거나 3번 모두 틀리면 해당 문제는 완료 상태가 된다. 정답을 맞힌 경우에는 축하 피드백과 함께 다음 문제 버튼을 활성화하고, 3번 모두 틀린 경우에는 정답을 먼저 보여준 뒤 같은 버튼을 활성화한다.

### 비폭력적 성취 피드백

행맨의 실패 이미지 대신 다음과 같은 표현을 사용한다.

- 별 또는 스티커가 채워지는 진행 표시
- 철자 단서를 완성했어요.
- 한 번 더 살펴보고 다음 도전으로 가요.
- 이번 단어의 철자를 확인했어요.

오답에는 큰 경고음이나 벌점 애니메이션을 사용하지 않는다. 입력이 틀렸을 때는 다시 시도할 수 있다는 메시지를 우선 보여준다.

## Game Rules

### Content selection

- 현재 학생이 불러온 단어 세트를 사용한다.
- 단어 세트의 원래 항목 순서와 중복 항목은 다른 활동과 동일하게 보존한다.
- 동일한 단어가 여러 항목으로 존재하면 각 출제마다 새로운 가림 패턴을 선택한다.
- 영어 단어가 없는 항목은 출제 대상에서 제외한다.
- 출제 가능한 단어가 하나도 없으면 게임 시작 전에 안내 메시지를 보여준다.

### Answer normalization

정답 비교는 다음 규칙을 적용한다.

- 영문 대소문자를 구분하지 않는다.
- 앞뒤 공백을 제거한다.
- 연속된 공백은 하나로 정규화한다.
- 단어 내부의 하이픈과 아포스트로피는 철자의 일부로 취급한다.
- 입력 정규화 결과가 정답 정규화 결과와 같을 때만 정답으로 인정한다.

### Mask generation

글자 수는 알파벳 글자만 세고, 공백·하이픈·아포스트로피는 화면에 항상 표시한다.

| 알파벳 글자 수 | 표시 단서 | 의도 |
| --- | --- | --- |
| 3~4 | 글자 1개 | 짧은 단어의 기본 단서 |
| 5~7 | 글자 2개, 내부 글자 최소 1개 | 앞부분 암기에만 의존하지 않게 함 |
| 8~10 | 첫 글자·끝 글자·내부 글자 1개 | 긴 단어의 구조 파악 지원 |
| 11 이상 | 첫 글자·끝 글자·내부 글자 2개 이상 | 긴 단어의 부담 완화 |

중간 단서 위치는 가능한 위치 목록에서 무작위로 선택한다. 같은 단어가 같은 세션에서 다시 출제될 경우 이미 사용한 마스크 서명을 피하고, 아직 사용하지 않은 패턴을 우선 선택한다. 가능한 패턴을 모두 사용한 경우에는 다시 선택할 수 있지만, 직전 패턴과 다른 패턴을 우선한다.

예시:

    apple    -> a _ p _ _
    computer -> c _ m _ _ _ t _

첫 번째 예시의 p와 두 번째 예시의 m, t처럼 중간 철자가 단서로 포함된다. 게임을 다시 시작하면 같은 단어라도 내부에 표시되는 위치가 달라질 수 있다.

### Attempts and scoring

문제당 입력 횟수는 최대 3회다.

| 결과 | 점수 |
| --- | ---: |
| 첫 번째 입력에서 정답 | 100점 |
| 두 번째 입력에서 정답 | 70점 |
| 세 번째 입력에서 정답 | 40점 |
| 세 번 모두 오답 후 정답 공개 | 10점 |

세 번째 입력에서 정답을 맞힌 경우에도 반드시 40점을 부여한다. 세 번 모두 오답이면 revealedCount를 1 증가시키고 정답을 공개한다. 완료된 문제에는 추가 입력을 허용하지 않는다.

최종 점수는 각 문제 점수의 합이다. 별도 시간 보너스나 콤보 보너스는 사용하지 않아 학생이 점수 계산을 쉽게 이해할 수 있게 한다.

## Leaderboard Design

### Activity definition

- type: spelling
- label: 철자 완성
- collectionName: spellingLeaderboards

기존 GameLeaderboardPanel에 spelling용 조회·저장 핸들러와 상세 지표 표시를 추가한다. 결과 화면에는 영어 철자 완성 LEADERBOARD section을 별도로 배치한다.

### Leaderboard document

경로는 다음과 같다.

    spellingLeaderboards/{scopeKey}/entries/{studentNameNormalized}

기록에는 다음 필드를 저장한다.

    schoolId
    schoolName
    grade
    studentName
    studentNameNormalized
    score
    correctCount
    questionCount
    accuracy
    revealedCount
    totalAttempts
    elapsedSeconds
    scopeKey
    periodType
    periodKey
    createdAt
    updatedAt

한 학생의 같은 기간 기록은 최고 점수만 유지한다. 점수가 같으면 정답 수가 많은 기록, 총 시도 횟수가 적은 기록, 소요 시간이 짧은 기록 순으로 우선한다.

### Student save flow

1. 결과 화면에서 학생이 이름을 입력한다.
2. 점수 저장 버튼을 누른다.
3. 기존 공통 저장 함수를 통해 주간·월간·연간·우리 학교 범위에 기록을 저장한다.
4. 일부 기간 저장에 실패하면 기존 화면 패턴대로 부분 성공 상태를 표시한다.
5. 저장 후 리더보드를 다시 조회해 최신 순위를 표시한다.

학교 또는 학년 정보가 없거나 Firebase 연결이 없으면 저장 버튼을 비활성화하고 이유를 안내한다.

### Teacher management

공통 활동 정의를 재사용해 교사 리더보드 화면에 철자 완성 탭을 표시한다. 교사는 기존 활동과 동일하게 현재 학교·학년의 이름 수정과 기록 삭제를 수행할 수 있다.

## Architecture and File Boundaries

### New game component

src/components/WordSpellingGame.jsx는 다음 책임만 가진다.

- 시작·플레이·결과 화면 상태 전환
- 현재 단어와 시도 상태 관리
- 키보드 입력과 문제 완료 처리
- 결과 화면에 철자 리더보드 section 연결

컴포넌트가 500줄에 가까워지면 결과 요약을 WordSpellingResult.jsx로 분리한다. 기존 WordTypingGame.jsx에는 새 게임 구현을 추가하지 않는다.

### Spelling utility

src/utils/wordSpelling.js는 UI와 독립적으로 다음 함수를 제공한다.

- 단어 항목 정규화
- 답안 정규화와 정답 판정
- 단어 길이별 가림 패턴 생성
- 세션 내 마스크 중복 방지
- 시도 횟수별 점수 계산
- 결과 지표 계산

이 파일은 랜덤 선택기에 주입 가능한 난수 함수를 지원해 테스트에서 패턴을 재현할 수 있게 한다.

### Existing shared layers

- src/App.jsx: APP_VIEWS.SPELLING와 지연 로딩 라우트 추가
- src/components/ModeSelector.jsx: 게임 버튼과 onOpenSpelling 연결
- src/utils/activityLeaderboard.js: spelling 정의와 동률 비교 규칙 추가
- src/components/GameLeaderboardPanel.jsx: 철자 활동의 조회·저장 핸들러와 표시 지표 추가
- src/lib/firebase.js: 철자 리더보드 조회·저장 API와 활동별 dispatch 추가
- firestore.rules: 철자 리더보드 학생·교사 권한과 지표 검증 추가
- src/constants/app.js: 버전과 업데이트 내역 추가
- docs/project-handoff.md: 기능과 데이터 구조 기록

## Data Flow

    현재 단어 세트
      -> 단어 항목 정규화
      -> 길이별 마스크 생성
      -> 키보드 답안 제출
      -> 정답 판정 및 문제 점수 계산
      -> 전체 결과 요약
      -> spellingLeaderboards 저장
      -> 주간·월간·연간·우리 학교 리더보드 재조회

리더보드 문서에는 정답 단어 자체나 학생의 입력 원문을 저장하지 않는다. 결과 비교에 필요한 집계 지표만 저장한다.

## Error Handling and Edge Cases

- 빈 입력: 영어 단어를 입력해 주세요. 안내 후 시도 횟수를 증가시키지 않는다.
- 3회 미만 오답: 입력창을 유지하고 다시 입력할 수 있게 한다.
- 3회 오답: 정답 공개 후 다음 문제를 활성화한다.
- 완료된 문제 재제출: 버튼과 Enter 입력을 잠가 중복 점수를 막는다.
- 단어에 공백·하이픈·아포스트로피가 포함된 경우: 구분 기호를 화면에 표시하고 정답 비교에도 반영한다.
- 출제 단어가 없는 경우: 홈으로 돌아가 단어 세트를 먼저 불러오도록 안내한다.
- Firebase 미설정: 게임은 로컬로 끝까지 진행하되 리더보드 저장 불가 이유를 결과 화면에 표시한다.
- 리더보드 일부 기간 저장 실패: 저장된 기간과 실패한 기간을 구분해 기존 공통 상태 문구로 안내한다.
- 컴포넌트가 화면에서 사라진 뒤 비동기 저장이 완료되는 경우: 취소 플래그로 상태 업데이트를 막는다.

## UI and Accessibility

- 마스크는 글자별 박스와 공백을 사용해 글자 수를 쉽게 파악하게 한다.
- 단서 글자와 빈칸의 색상 대비를 기존 디자인 시스템 기준 이상으로 유지한다.
- 입력창에는 명확한 label과 placeholder를 제공한다.
- 현재 문제 번호, 시도 횟수, 완료 상태를 스크린 리더가 읽을 수 있게 한다.
- 게임 시작, 입력 확인, 다음 문제, 점수 저장 같은 핵심 버튼에는 gi-pulse 강조 효과를 적용한다.
- prefers-reduced-motion 환경에서는 강조 애니메이션을 줄인다.
- 좁은 화면에서는 입력창과 버튼을 세로로 배치하고, 결과 리더보드가 가로로 넘치지 않게 한다.

## Testing Strategy

### Unit tests

src/utils/wordSpelling.test.js에 다음을 검증한다.

- 단어 길이별 표시 글자 수
- 긴 단어에서 내부 단서가 반드시 포함되는지
- 세션 내 마스크 서명 중복 방지
- 대소문자·공백 정규화
- 하이픈·아포스트로피 처리
- 1·2·3번째 정답의 100·70·40점
- 3회 오답 후 10점과 정답 공개 상태
- 완료 후 추가 제출 방지에 필요한 결과 상태

### Leaderboard and Firebase tests

- spelling 활동 정의와 별도 컬렉션 이름
- 철자 리더보드 저장·조회 dispatch
- 점수·정답 수·시도 횟수 기준 동률 비교
- 교사 리더보드 탭에 철자 활동이 포함되는지

### Firestore rules tests

- 학생이 자신의 정규화된 이름 문서만 생성할 수 있는지
- 다른 학생 이름이나 학교·학년을 가장한 저장이 차단되는지
- 점수가 낮은 기록으로 기존 최고 기록을 덮어쓰지 못하는지
- 교사가 자신의 학교 기록만 수정·삭제할 수 있는지
- 음수 점수, 잘못된 문제 수, 3회를 초과한 시도 횟수가 차단되는지

### Browser smoke checks

- 홈에서 버튼 순서가 단어 낚시 → 철자 완성 게임 → 영어 단어 타자 게임인지
- 짧은 단어와 긴 단어의 마스크가 다르게 표시되는지
- 게임 재시작 때 내부 단서 위치가 바뀌는지
- 세 번째 시도 정답이 40점으로 반영되는지
- 세 번 모두 오답일 때 정답과 다음 문제 버튼이 표시되는지
- 결과 화면의 철자 리더보드 section에서 이름과 점수 저장이 가능한지
- 교사 화면에서 철자 리더보드 탭과 기록 관리가 가능한지

## Acceptance Criteria

- 학생 홈에 새 버튼이 정확한 위치에 표시된다.
- 키보드로 전체 단어를 입력할 수 있다.
- 단어 길이에 따라 단서 수가 달라지고 긴 단어에는 내부 글자가 포함된다.
- 게임을 다시 시작하면 같은 단어의 내부 단서 위치가 가능한 범위에서 달라진다.
- 첫·두 번째·세 번째 정답이 각각 100·70·40점으로 계산된다.
- 세 번 모두 틀린 문제는 10점과 함께 정답 공개 및 다음 문제 진행이 가능하다.
- 철자 게임 점수가 타자 리더보드와 분리된 리더보드에 저장된다.
- 학생 이름과 점수를 저장한 뒤 최신 순위를 확인할 수 있다.
- 교사가 철자 리더보드 기록을 기존 방식으로 관리할 수 있다.
- 기존 활동의 테스트와 동작이 깨지지 않는다.
