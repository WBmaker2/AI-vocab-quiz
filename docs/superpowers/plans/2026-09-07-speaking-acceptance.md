# 말하기 인정 기준의 제한적 개선

## 목표와 범위
음성인식 오류로 인한 좌절을 줄이되 서로 다른 단어를 무분별하게 정답 처리하지 않는다. 실제 발음 채점이 아니라 인식 문자열 보완이라는 한계를 유지한다. 구현은 Luna가 수행한다.

## 판정 계약
- 최대 3개 최종 인식 후보를 개별 문자열로 보관한다. 대안들을 이어 붙여 가짜 문장이나 구절을 만들지 않는다. 학생에게는 첫 후보를 표시한다.
- 첫 후보는 기존 판정을 기본으로 한다. cat/cut, ship/sheep, rice/lice, red/led, three/tree 같은 명시적 혼동 쌍은 보호한다. 숫자 의미가 달라지는 경우와 구절 일부만 발화한 경우를 보호한다.
- 추가 후보는 목표 전체와 정규화 후 정확하게 일치하고 첫 후보가 보수적인 근접 조건을 만족할 때만 인정한다. 공백·숫자 표기 정규화는 허용하되 짧은 단어, 숫자 차이, 핵심 자음 차이를 추가 후보로 우회하지 못하게 한다.
- 모든 단어에 대한 편집거리 확대나 새 발음 치환은 하지 않는다. 실제 음성 자료 없이 임의의 오인식 목록을 늘리지 않는다. confidence를 발음 점수나 일률적 통과 기준으로 사용하지 않는다.
- 후보가 1개뿐인 브라우저에서도 정상 작동한다. 새 시도와 초기화 시 후보를 비운다. 일반 연습과 복습에 동일하게 적용한다.
- 재도전 문구는 인식 결과를 중립적으로 설명하고 다시 듣기·말하기를 권한다. 기존 시도 횟수와 점수 계약은 유지한다.

## 구현 순서
1. 음성 결과 추출과 후보 판정 유틸을 분리하고 정상/거부 회귀 테스트를 작성한다.
2. useSpeechRecognition에서 후보를 전달하고 SpeakingQuiz 일반/복습 흐름에 연결한다.
3. 재도전 문구와 업데이트 내역을 갱신한다. 신규 파일은 500줄 미만으로 유지하고 말하기의 관련 로직은 작은 파일로 분리한다.
4. 단위 테스트, 빌드, diff 검사와 가능한 로컬 브라우저의 모의 음성인식 회귀를 수행한다. 실제 학생 음성 검증과 모의 검증을 구분한다. VoiceOver 검증은 제외한다.
5. 변경 문서에 결과와 HVC 확인 방법을 남긴다. 커밋·푸시·배포는 이번 범위에 포함하지 않는다.

## 필수 검증
- 추가 후보의 정확한 답 + 허용된 근접 첫 후보만 인정한다.
- 무관한 첫 후보 + 추가 후보의 정답은 거부한다.
- 보호 혼동 쌍, 다른 숫자, 짧은 단어 차이, 잘린 구절은 거부한다.
- 대안 사이의 문자열 합성으로 정답이 만들어지지 않는다.
- 중간 결과로 채점하지 않고, 초기화 시 이전 후보가 남지 않는다.
- 기존 숫자 표기·공백·보수적 유사 발음 테스트를 유지하되 three/tree는 보호 기준에 맞춘다.
