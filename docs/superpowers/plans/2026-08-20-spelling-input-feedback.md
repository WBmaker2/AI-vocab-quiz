# 철자 완성 입력창·오답 피드백 개선 계획

## 목표

철자 완성 게임에서 긴 영어 단어도 편하게 입력할 수 있도록 입력창을 넓히고, 학생이 오답을 입력할 때마다 즉시 상황을 이해하고 다음 행동을 고를 수 있는 피드백 모달을 제공한다.

## 확인된 원인

1. 현재 입력 폼은 `minmax(0, 1fr) max-content` 한 줄 구조다. 데스크톱에서는 입력창이 남은 공간을 사용하지만, 좁은 화면에서는 버튼의 고정 최소 너비와 간격이 입력창 폭을 크게 줄인다.
2. `WordSpellingGame`은 오답 문구만 `feedbackMessage` 상태에 넣고, `questionCompleted`가 된 경우에만 `WordSpellingFeedbackModal`을 렌더링한다. 1·2번째 오답은 화면 아래의 일반 피드백 상태만 바뀌므로 학생이 즉시 알아차리기 어렵다.

## 구현 범위

### 입력창

- 철자 입력 폼을 전체 너비 기준으로 유지하고, 데스크톱에서는 입력창이 남은 공간을 우선 사용하도록 한다.
- 확인 버튼은 고정된 작은 폭으로 제한한다.
- 720px 이하에서는 입력창을 한 줄 전체로 먼저 보여주고 확인 버튼을 아래에 작게 배치해 긴 답을 입력할 가로 공간을 보장한다.
- 360px 폭에서도 가로 넘침이 없어야 한다.

### 오답 피드백 모달

- 3회 제한에 도달하지 않은 오답 제출마다 모달을 연다.
- 모달에는 다음과 같은 학생 친화적 문구를 표시한다.
  - `아쉽지만 틀렸습니다.`
  - `다시 시도해 볼까요?`
  - 힌트가 남아 있으면 `힌트를 하나 더 열어볼까요?`
- `다시 시도하기`는 모달을 닫고 입력창으로 포커스를 돌린다.
- `힌트 하나 더 열기`는 모달을 닫고 기존 힌트 단계를 한 단계 진행한다.
- 마지막 오답은 기존 결과·진행 모달 흐름을 유지하되, 학생이 오답임을 명확히 알 수 있는 문구를 사용한다.
- 모달이 열린 동안 배경 스크롤을 잠그고, 기본 포커스와 Enter/Space 버튼 동작을 유지한다.

## 검증 기준

- 긴 단어 입력창이 데스크톱에서 확인 버튼보다 확실히 넓다.
- 360px, 480px, 768px, 1280px 화면에서 입력 폼이 잘리지 않는다.
- 첫 번째·두 번째 오답마다 피드백 모달이 열린다.
- `다시 시도하기`와 `힌트 하나 더 열기`가 각각 정확한 상태로 돌아간다.
- 세 번째 오답은 기존처럼 문제를 완료하고 다음 문제 모달을 보여준다.
- `npm test`, `npm run build`, `npm run test:smoke`를 통과한다.

## 제외 범위

- 철자 점수 계산, 시도 횟수, 힌트 공개 규칙은 변경하지 않는다.
- Firebase 저장 구조와 리더보드 데이터는 변경하지 않는다.
