# Playwright 스모크 테스트 안정화 계획

## 목표

CI와 로컬 제한 환경에서 브라우저가 실행되지 않거나, Firebase의 백그라운드 요청 때문에 실제 화면이 준비된 뒤에도 `networkidle` 대기가 시간 초과하는 문제를 줄인다.

## 배경

현재 `scripts/playwright_smoke.js`는 `chromium.launch()`를 환경별 옵션 없이 실행하고, `page.goto()`에서 모든 네트워크 요청이 잠잠해지는 `networkidle` 상태까지 기다린다. 이 방식은 앱 화면이 정상적으로 보이는 상황에서도 실행 환경의 권한 제약, Chromium 크래시, Firebase 인증·Firestore 등의 지속적인 백그라운드 요청 때문에 테스트가 시작되기 전에 실패할 수 있다.

## 구현 범위

### 1. 테스트 브라우저 실행 옵션

- 스모크 테스트에만 적용되는 제한 환경 대응 launch 옵션을 상수로 분리한다.
- 기본값은 일반 Chromium 실행을 유지하고, `CI` 또는 `PLAYWRIGHT_RESTRICTED_ENV=1`일 때만 제한 환경 옵션을 적용한다.
- 운영 앱 코드나 배포 번들에는 이 옵션을 넣지 않는다.
- 샌드박스 비활성화는 격리된 CI/로컬 테스트에서만 사용한다는 주석과 문서 설명을 남긴다.

### 2. 견고한 페이지 준비 대기

- `networkidle` 대신 `domcontentloaded`를 첫 준비 기준으로 사용한다.
- HTML이 준비된 뒤 랜딩 제목·업데이트 내역 버튼·버전 표시처럼 실제 스모크에 필요한 요소가 표시될 때까지 명시적으로 기다린다.
- `pageerror`, 로컬 정적 리소스 요청 실패, 로컬 HTTP 오류를 수집해 테스트 실패 시 원인을 함께 출력한다.
- Firebase의 계속되는 백그라운드 통신을 전체 페이지 준비 조건으로 사용하지 않는다.

## 검증 기준

- 기본 모드에서 기존 스모크 흐름이 통과한다.
- `PLAYWRIGHT_RESTRICTED_ENV=1 npm run test:smoke`에서도 같은 스모크 흐름이 통과한다.
- 업데이트 내역, 활동 버튼 순서, 반응형 가로 넘침, 학교 검색 Enter, 교사 화면 진입 검사가 계속 동작한다.
- `npm test`와 `npm run build`가 통과한다.
- 변경 내용과 환경별 실행 방법을 `docs/changes/`에 별도 기록한다.

## 제외 범위

- Firebase 인증·Firestore 설정 자체를 변경하지 않는다.
- 실제 앱의 로딩 UI나 사용자 기능을 변경하지 않는다.
- 브라우저 권한 오류를 앱 로직 오류로 간주하지 않는다.
