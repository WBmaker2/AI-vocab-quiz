# 초등학생 학습 흐름 개선 구현 계획

## 목표

2026-09-07 학생 관점 감사에서 확인한 철자 완성 게임의 모바일 진행 차단과 통계 오해를 먼저 해결한다. 학생이 틀린 뒤 다음 행동을 찾고, 도움을 받은 정도를 결과에서 정확히 이해하며, 좁은 화면에서도 문제를 끝까지 완료할 수 있게 한다.

## 범위

이번 구현은 다음 항목을 포함한다.

1. 철자 피드백 모달을 `document.body` 포털로 렌더링해 부모 카드의 `backdrop-filter`가 fixed 위치 기준을 바꾸지 않도록 한다.
2. 모바일 모달의 내부 스크롤, 하단 행동 버튼, 포커스 순환과 닫힌 뒤 입력창 복원을 보장한다.
3. 진행 중 정확도는 아직 풀지 않은 문제를 분모에 포함하지 않고 `푼 문제 기준 정확도`로 표시한다. 전체 결과 카드의 최종 정확도는 기존처럼 전체 문제 기준으로 유지한다.
4. 힌트를 한 단계 이상 사용한 뒤 정답을 입력한 경우를 `도움을 받아 맞힌 문제`로 기록한다. 기존 `revealedCount`는 세 번 오답으로 자동 공개된 문제와 구분되므로, 별도 `hintUsedCount`를 추가한다.
5. 힌트 사용에 맞는 점수·리더보드 검증을 추가한다. 힌트를 썼다는 이유만으로 점수를 0점 처리하지 않되, 결과 화면에서 학습 도움과 자동 공개를 구분한다.
6. 빈 입력 시 학생이 즉시 확인할 수 있는 안내를 표시하고 기회·점수는 줄이지 않는다.
7. 이 흐름을 순수 유틸 테스트와 현재 브라우저 시나리오로 재검증한다.

이번 단계에서 홈 화면 전체 재설계, 운영 주소 통합, Firebase 작성자 인증, 장기 오답 복습, 대규모 파일 분리는 별도 후속 작업으로 남긴다. 기능 계약을 바꾸는 Firestore 필드가 추가되므로 클라이언트 저장, Firebase 검증, 규칙, 교사 리더보드 표시를 함께 갱신한다.

## 구현 순서

### 1. 계획과 계약 고정

- [x] 이 문서를 `docs/superpowers/plans/`에 저장한다.
- [x] `hintUsedCount`를 힌트를 한 단계 이상 사용해 맞힌 문제 수로 정하고, `0 <= hintUsedCount <= correctCount` 범위를 적용한다.
- [x] 기존 `revealedCount`, `totalAttempts`, 점수 계산과의 호환을 확인한다.

### 2. 모달 레이어와 키보드 흐름

- [x] `WordSpellingFeedbackModal`을 `createPortal`로 body에 렌더링한다.
- [x] Tab/Shift+Tab을 모달 안에서 순환시키고, 최초 포커스와 종료 후 입력창 포커스를 확인한다.
- [x] 320×800, 375×800, 1280×800에서 backdrop은 viewport를 채우고 모달 내용만 스크롤되도록 CSS를 조정한다.

### 3. 철자 상태·통계

- [x] 문제별 `hintUsed` 상태를 추적하고 힌트를 사용한 정답 입력을 별도 카운트한다.
- [x] 진행 모달의 정확도를 `correctCount / completedQuestionCount`로 계산한다.
- [x] 빈 입력 메시지를 렌더링하고 입력창을 다시 활성화한다.
- [x] 결과 카드와 리더보드 payload에 `hintUsedCount`를 전달한다.

### 4. 저장·검증 계약

- [x] `spellingLeaderboard` validator와 Firestore rules에 `hintUsedCount`를 추가한다.
- [x] 기존 데이터는 조회·표시에서 필드가 없으면 0으로 읽고, 새 저장은 검증된 필드를 포함하도록 하위 호환을 유지한다.
- [x] 교사 리더보드와 학생 결과에서 `도움 사용`을 표시한다.

### 5. 테스트와 브라우저 검증

- [x] 힌트 사용 판정, 세 번 오답 자동 공개 계약, 빈 입력, 진행 정확도에 대한 유틸·규칙 테스트를 추가한다.
- [x] `npm test`, `npm run build`, `git diff --check`를 실행한다.
- [x] 공개 데이터가 아닌 로컬 개발 화면에서 시작→빈 입력→오답→힌트→정답→완료를 수행한다.
- [x] 같은 viewport에서 모달 버튼 위치와 포커스를 다시 측정한다.

검증 결과: `npm test`는 167개 통과·79개 에뮬레이터 전용 건너뜀, `npm run test:rules`는 79개 통과, `npm run build`와 `git diff --check`는 통과했다. Playwright smoke는 로컬 Chromium 실행 파일이 없어 실행하지 못했으며, 동일 흐름은 ego-browser 로컬 화면에서 확인했다.

## 수용 기준

- 320×800과 375×800에서 결과/오답 모달의 주요 버튼을 추가 스크롤 없이 누를 수 있다. 내용이 길면 모달 내부에서 스크롤된다.
- 모달이 열린 동안 Tab은 배경으로 빠지지 않는다.
- 첫 문제를 맞혔을 때 진행 모달은 `1 / 전체`, `푼 문제 기준 정확도 100%`를 보여준다.
- 힌트를 한 단계 이상 사용한 뒤 맞힌 문제는 `도움 사용`에 포함되고, 세 번 오답으로 자동 공개된 문제는 `정답 공개`에 포함된다.
- 빈 입력은 기회를 소비하지 않으며 `먼저 영어 단어를 써 주세요.`와 같은 회복 안내가 실제 화면에 보인다.
- 기존 리더보드 필드와 점수 계산은 이전 기록을 읽을 수 있고, 새 필드의 값은 모순된 상태를 규칙에서 거부한다.

## 제외 및 제한

- 실제 초등학생 참여 연구, VoiceOver 인증, 실제 마이크 품질 검증은 이번 구현의 수용 증거가 아니다.
- 커밋·푸시·배포는 별도 요청이 없으므로 수행하지 않는다.
- Firebase 에뮬레이터가 준비되지 않으면 규칙 검증은 차단 상태로 보고하고 기존 캐시를 임의 대체하지 않는다.
